# FAST-LIO2 reproduction log

Implements `FAST-LIO2-Docker-Reproduction-Guide.pdf` (rev. 2, 6 Oct 2026) against
Xu et al., *FAST-LIO2: Fast Direct LiDAR-Inertial Odometry*, IEEE T-RO 2022
(arXiv 2107.06829). This file records what was done, what deviated from the guide
and why, and every result. Results tables are regenerated by
`scripts/eval_fastlio2.sh` into `output/results/fastlio2_<timestamp>/comparison.md`.

## How to reproduce one sequence

```bash
docker build -t evtol/base:noetic -f docker/base.Dockerfile .
docker build -t evtol/fastlio2:v1 -f docker/fastlio2.Dockerfile .
docker build -t evtol/eval:v1     -f docker/eval.Dockerfile .

# 5 runs in 5 parallel containers (identical to serial runs -- verified)
bash scripts/fl2_parallel.sh 5 run_fastlio2.sh /config/fastlio2/<cfg>.yaml /data/<...>.bag <seq>
# ground truth if the paper scores RMSE (see table below), then:
docker compose run --rm -T eval bash /scripts/eval_fastlio2.sh
```

| Dataset | Config | Runner | Ground truth |
|---|---|---|---|
| lili (KA-Urban) | `lili.yaml` | `run_fastlio2.sh` | none (end-to-end); GNSS proxy `gnssref_<seq>.tum` from `/gnss` |
| liosam park/garden | `liosam_park_garden.yaml` | `run_fastlio2.sh` | park: GPS in bag |
| liosam campus | `liosam_campus.yaml` | `run_fastlio2.sh` | none (end-to-end) |
| nclt | `nclt.yaml` | `nclt_to_bag.sh`, then `run_fastlio2.sh` | `fl2_gt.py nclt groundtruth_<date>.csv` |
| utbm | `utbm.yaml` + `utbm_convert.launch` | `run_fastlio2_utbm.sh` | `utbm_gt.sh`, then `fl2_gt.py bag <seq>_fix.bag /fix` |
| ulhk | `ulhk.yaml` | `run_fastlio2.sh` | `/novatel_data/inspvax` (not run, see below) |

Paper parameters (Sec. VI-A) are forced by the runners for every dataset:
`point_filter_num 4`, `filter_size_surf/map 0.5`, `cube_side_length 1000`,
`max_iteration 3`, direct method. The parameters actually used are dumped next to
each run as `<seq>_r<N>.params.yaml`.

## Verified against primary sources (2026-10-06)

- Pins: Livox-SDK v2.3.1 = `14c533d`, livox_ros_driver v2.6.0 = `fb5669b`,
  FAST_LIO HEAD = `7cc4175` (git ls-remote); evo 1.31.1 in the eval image.
- Paper targets (Tables IV, V, VIII) and defaults (Sec. VI-A) match the guide.
- FAST_LIO reads `point_filter_num` etc. as global params (`laserMapping.cpp`), so
  `rosparam set /point_filter_num 4` is effective.
- lili IMU: paper Table II lists lili's IMU as "6-axis, 200 Hz" = the Horizon's
  built-in `/livox/imu`, not the 9-axis Xsens `/imu/data`.
- NCLT extrinsic re-derived independently from NCLT paper Table 4 and the authors'
  converter: identical to the guide's matrix (1.08 deg from identity).
- LIO-SAM: README confirms park/garden use `/imu_raw` + diag(-1,1,-1); campus uses
  `/imu_correct` + identity.

## Corrections to the guide

| # | Guide says | Found | Fix |
|---|---|---|---|
| 1 | `kill -INT` + `wait` stops FAST-LIO | FAST-LIO overrides SIGINT; with `use_sim_time` its loop blocks forever on the stopped `/clock` -- every run hangs | timed SIGINT -> SIGKILL in both runners (odometry bag already closed) |
| 2 | helpers run with `python3` in the eval container | eval venv has no `rosbag` | helpers re-exec with system python + ROS path |
| 3 | `bash -lc 'rospack find ...'` checks | `-l` does not read `.bashrc`, ROS not sourced | source ROS explicitly |
| 4 | NCLT Drive folder has converted bags | it holds only the converter + `topic_name` | `nclt_to_bag.sh` runs the authors' converter (vendored verbatim) on NCLT raw data |
| 5 | (converter runs as is) | Ubuntu 20.04 scipy 1.3 lacks `Rotation.from_matrix` | runtime alias to `from_dcm`; script unchanged |
| 6 | `utbm_convert.launch` uses `velodyne_pointcloud/cloud_node` | not shipped in Noetic's 1.7.0 -- launch starts nothing | `TransformNodelet` in a nodelet manager |
| 7 | UTBM cloud may lack per-point time; `timestamp_unit: 2` | converted cloud has `time` in **seconds** | `timestamp_unit: 0` (2 would scale by 1e-3 and disable de-skew) |
| 8 | liosam `timestamp_unit: 2` | LIO-SAM README: per-point time is seconds | `timestamp_unit: 0`, to be confirmed with `fl2_cloudcheck.py` on the bag |
| 9 | garden is a "small bag" | 10.5 GB (park 3.5, campus_large 4.9) | -- |
| 10 | lili end-to-end = first-to-last gap | KA-Urban bags do not end at their start; LiLi-OM scores against unpublished satellite-registered end points | report first-to-last as not comparable + GNSS end-point proxy (`fl2_endref.py`) |
| 11 | paper Table VIII: nclt 9 = 0.26 km | GT path is 1139 m; Semi-Elastic LIO lists 1.1 km | paper typo |

## Findings on the paper's numbers

**NCLT/UTBM/ulhk RMSE protocol.** The paper does not state its alignment. A
standard full-trajectory SE(3) Umeyama alignment (evo `--align`) gives far lower
RMSE than Table IV. An independent re-run of FAST-LIO2 (Yuan et al., *Semi-Elastic
LiDAR-Inertial Odometry*, arXiv 2307.07792, Table II) shows the same thing on all 9
shared sequences: 2-8x below the FAST-LIO2 paper. Both references are reported;
sensitivity on nclt 9 run 1:

| evo alignment | RMSE (m) |
|---|---|
| `--align` (full SE(3)) | 0.954 |
| `--align --n_to_align 1000` (first ~100 s) | 4.20 |
| `--align_origin` / none | 371 / 287 (frames differ) |

**lili 7 diagnostics** (one run each, Schloss-2):

| Variant | first-to-last | end vs GNSS |
|---|---|---|
| paper config (Horizon IMU, pfn 4, extrinsic est. on) | 11.3 m | 8.9 m |
| Xsens `/imu/data`, zero extrinsic (guide fallback) | diverges (22 km) | - |
| extrinsic estimation off | 11.3 m | 8.9 m |
| `point_filter_num 3` (upstream launch value) | 14.7 m | 12.3 m |

The paper configuration is the best of these. Remaining hypothesis: the paper used
the July-2021 FAST_LIO code; the pin is the 2023+ HEAD.
