# FAST-LIVO2 reproduction log

Implements `FAST-LIVO2-Docker-Reproduction-Guide.pdf` (7 Oct 2026) against Zheng et al.,
*FAST-LIVO2: Fast, Direct LiDAR-Inertial-Visual Odometry*, IEEE T-RO (arXiv 2408.14035),
code `hku-mars/FAST-LIVO2` @ `0d2c034`. Records what was done, where the guide was wrong,
and every result. Tables are regenerated by `scripts/eval_fastlivo2.sh`; the final ones are in
`docs/results/fastlivo2_{standard,matched}_comparison.md` (per-run values in `*_summary.csv`).

## How to reproduce

```bash
docker build -t evtol/fastlivo2:v1 -f docker/fastlivo2.Dockerfile .   # needs evtol/base:noetic
# everything that is downloaded, unattended (survives a closed terminal):
systemd-run --user --unit=livo2-bench --collect --working-directory=$PWD bash scripts/livo2_benchmark.sh
# NTU-VIRAL "matched start" protocol (after the standard runs exist):
bash scripts/livo2_ntu_matched.sh
# single sequence, 5 parallel runs:
SERVICE=fastlivo2 bash scripts/fl2_parallel.sh 5 run_fastlivo2.sh \
    /config/fastlivo2/NTU_VIRAL.yaml /config/fastlivo2/camera_NTU_VIRAL.yaml \
    /data/ntu_viral/eee_02/eee_02/eee_02.bag eee_02
docker compose run --rm -T eval bash /scripts/eval_fastlivo2.sh
```

## Verified against primary sources (2026-10-07)

- Pins: FAST-LIVO2 `0d2c034`, rpg_vikit (xuankuzcr) `6c886c8`, Sophus `a621ff` (+ the two-line C++11
  patch, which applies and builds). Livox driver not needed (CustomMsg vendored).
- Paper Table II values and Sec. IX-A defaults match the guide.
- **Step 3 gate passed:** the authors' shipped `Log/result/ntu_viral/*` re-score with our eval image to
  2.71/2.11/2.61/3.57/3.39/3.52/2.35/2.84/3.12 cm (README: 2.71/2.11/2.61/3.56/3.39/3.52/2.34/2.83/3.11).
  Our ground truth is byte-identical to theirs (`gt_eee_02`: max abs diff 0.0).
- `viral_prep.py` (numpy) = authors' scipy `evaluate_viral.py` to 5e-7 m on 1000 random poses.
- Parameters: main config is read through a global NodeHandle (global `rosparam load` is right);
  camera via `loadFromRosNs("laserMapping")` -> `/laserMapping/cam_*` (confirmed in the node log).
- Trajectory file is re-opened and appended with `std::endl` per frame (no loss on forced stop);
  subscriber queues are 200000 (lag buffers, never drops), so parallel runs cannot change the data seen.
- Between the results commit (2025-03-29) and the pin, `vio.cpp`/`voxel_map.cpp` are unchanged;
  later `LIVMapper.cpp` changes are output formats and a Hilti-only frame skip -> same NTU algorithm.

## Corrections to the guide

| # | Guide says | Found | Fix |

result is bimodal (4.6 / 8.4 cm); the authors' single run (3.4 cm) lies outside both modes.
